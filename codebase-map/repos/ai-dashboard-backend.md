# ai-dashboard-backend

## What it is
Dashboard CRUD service with Hibernate Envers audit and a state/city lookup. Derived from a Quarkus K8s template. No outbound REST clients, no Pub/Sub, no exotic concurrency. Scope is narrow and the implementation is clean. ~2,000 LOC Java. Fleet-review verdict: **ship-as-is**.

## How it fits
- Consumes API of: none observed
- Publishes events to: none observed
- Owns data store: PostgreSQL (dashboards, cities, states + Envers audit tables)
- Owns no data; pure orchestrator: false

## Build / test / run
```
mvn clean package
mvn test
mvn quarkus:dev
```

## Key abstractions
- `CityResource` / `StateResource` — `resource/` — REST boundary; path/body ID consistency check at `CityResource.java:189-193`
- `CityRepository` / `StateRepository` — Panache typed repositories
- `findByPublicIdAllowDeactivated` — native query method on both repositories; one of the few risk surfaces

## Don't-do-here / gotchas
- The native `findByPublicIdAllowDeactivated` queries on `CityRepository.java:110-113` and `StateRepository.java:94-98` have no query timeout — verify a Postgres index on `cities.public_id` and `states.public_id` and set `hibernate.query.timeout=30000` ms.
- Production datasource `max-size` unspecified (`application.properties:72`); for a CRUD service this is probably fine but make it explicit (`quarkus.datasource.jdbc.max-size=30`).
- `StateResource.java:180-183` has a duplicate `@APIResponse` annotation for HTTP 400 — cosmetic only.
- Pagination is sanity-bounded (page ≤ 0 → 1, size ≤ 0 → DEFAULT_PAGE_SIZE) — keep this when extending.
