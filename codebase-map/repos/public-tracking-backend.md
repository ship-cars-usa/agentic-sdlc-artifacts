# public-tracking-backend

## What it is
Spring Boot 3.2.12 / Java 21 **public-facing** load-tracking API (the customer/recipient-facing surface — Keycloak is intentionally **disabled**: `keycloak.enabled=false`, `ship-cars-commons-spring.rest.keycloak.enabled=false`). Exposes a small REST surface (`GET /v1/loads`, FE-customization metadata) protected by **Google reCAPTCHA v3** (score-vs-threshold) with attempt-limited bot blocking. Consumes two Pub/Sub subscriptions to keep its tracking read-model warm. Uses Unleash for feature toggles (`public-tracking` and `captcha` flags). Single-module hexagonal Spring Boot (`adapters/in|out`, `domain`, `config`) — much simpler than the rest of the operations domain.

## How it fits
- Consumes API of: Google reCAPTCHA (v3 siteverify, external), `location-provider` (via `ship.cars.locationprovider:spring-client` **3.28.0**), Unleash feature-flag server, `media-proxy` (image URLs). Calls go through `spring-commons` `WebClientImpl` — **no explicit per-client timeouts** (relies on commons defaults).
- Publishes events to: none observed.
- Subscribes to: Pub/Sub **`ctms-state`** (`CtmsStateConsumer` — legacy CTMS load/vehicle/attachment state) and **`load-info-state`** (`LoadMateLoadStateConsumer` — LoadMate/Lite load state). Both configured via `config.pubsub.subscriptions[...]` (`application.properties:29-30`). JSON DTOs over Pub/Sub — no schema registry.
- Owns data store: PostgreSQL — **HikariCP `maximumPoolSize=5`, `connectionTimeout=20000ms`** (`application.properties:52-53`; extreme outlier for a public-facing API — see Don't-do-here). Spring Data Envers auditing enabled. Flyway disabled at boot (`spring.flyway.enabled=false`, `:34`) — migrations run as a separate job.

## Don't-do-here / gotchas
- **HikariCP `maximumPoolSize=5` on a public-facing API** — under a concurrent spike (dispatcher links shared en masse) pool exhaustion is the first failure mode. Right-size (≥16) after a load test.
- **No REST-client timeouts** — captcha / location-provider / media-proxy calls inherit `WebClientImpl` defaults. A slow reCAPTCHA endpoint hangs the request thread; combined with pool=5 the service saturates quickly.
- **Unleash on the request path** — if Unleash is unreachable with no cached default, feature-gated endpoints (incl. the `captcha` gate itself) can misbehave. Confirm offline-fallback config.
- **Flyway disabled at boot** — pods can start against an unmigrated schema if the K8s job ordering breaks; verify init-container / job-precedence.
- **Two overlapping Pub/Sub subscriptions** (`ctms-state`, `load-info-state`) carry overlapping load facts from two source systems (CTMS + LoadMate); consumer-side ordering/merge matters.
- **No rate limiting beyond captcha** — a bot that passes captcha once can hammer `GET /v1/loads`. Consider per-IP rate limiting.
