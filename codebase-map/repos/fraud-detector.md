# fraud-detector

## What it is
Quarkus 3.15.2 / Java 21 service that ingests platform events (loads, vehicles, negotiations) plus user/company context, maintains **risk-factor tables** (route deviation, early cancellation, expensive load, etc.), and computes per-company / per-user **overall risk scores**. Pushes alerts to a Slack channel and to a Pub/Sub fraud-alerts topic. Reads vehicle MSRP from an external lookup. Provides REST endpoints for risk queries and per-company configuration.

## How it fits
- Consumes API of: external `VehicleClient` (`@RegisterRestClient`, **`baseUri="https://done.ship.cars"` hardcoded** in the client interface — see Don't-do-here) for MSRP lookup; `SlackClient` for alert posting; **DataOne** token-auth flow. **No `quarkus.rest-client.*.connect-timeout` / `read-timeout` configured for any client.**
- Publishes events to: Pub/Sub `fraud-alerts-topic`.
- Subscribes to: Pub/Sub `platform-subscription` (PlatformMessageObjectDto: loads / vehicles / negotiations), `keycloak-subscription` (KeyCloakEventDto), `user-management-user-subscription`, `user-management-company-subscription`.
- Owns data store: PostgreSQL (`frauddetector` db, HikariCP max-size=16 dev), Hibernate, Flyway.

## Key abstractions
- `RiskDetectorResource` — `resources/.../RiskDetectorResource.java` — REST endpoints for company/user risk scoring queries.
- `RiskFactorTriggerService` — `services/.../RiskFactorTriggerService.java` — orchestrates risk-factor recalculation after relevant events.
- `RiskFactorOverallScoreService` — computes composite per-company/user score from underlying factors.
- `PlatformPubSubListener` — `services/listeners/.../PlatformPubSubListener.java` — consumes `platform-subscription`; routes events to the right risk-factor calculators.
- `KeyCloakPubSubListener` / user / company listeners — ingest identity & ownership context.

## Don't-do-here / gotchas
- **`VehicleClient.baseUri="https://done.ship.cars"` is hardcoded in the `@RegisterRestClient` annotation** — not env-overridable in any non-prod environment without a code change. Switch to `@RegisterRestClient(configKey="...")` and read the URL from properties.
- **No REST-client timeouts** on `VehicleClient`, `SlackClient`, or DataOne — same fleet pattern. With `@Retry` (if present elsewhere on these clients) this becomes the standard cascading-failure shape.
- **Quarkus 3.15.2 — two minors behind the fleet (3.20.x / 3.27.x)**. Plan an upgrade in the next maintenance window.
- **Slack + email alerts are feature-flagged off** in non-prod (`frauddetector.email.enabled=false`) — easy to forget to flip on after a deploy. Add a startup health-check that warns if the feature is disabled in prod.
- **No observed cap on risk-factor recalculation** — if a single event triggers a large recompute, watch DB latency and Hibernate session size. Consider batching or a dedicated worker queue.
- **Direct Pub/Sub publish to `fraud-alerts-topic`** — no outbox; same observation as elsewhere in the fleet.
