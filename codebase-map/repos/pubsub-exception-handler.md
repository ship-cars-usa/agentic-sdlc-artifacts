# pubsub-exception-handler

## What it is
**Internal service for capturing undeliverable Pub/Sub messages** — subscribes to **Dead Letter Queues (DLQs)** across the fleet and stores the dead messages in a relational database for monitoring + analysis. Per the README:

> The PubSub Exception Handler is an internal service designed to manage undeliverable Pub/Sub messages by capturing those routed to Dead Letter Queues (DLQs) and storing them in a relational database. This facilitates efficient monitoring and management of message failures.

Key features (per README):
- Intercepts messages from specified DLQs.
- Records them in a relational database (Postgres) for downstream analysis / replay / metrics.

**Complements `quarkus-pubsub`'s GCP-side retry/DLQ posture**: `quarkus-pubsub` itself doesn't have in-code retry — it relies on the GCP subscription's `Maximum delivery attempts` + `Dead letter topic` config. This service is the **fleet's central DLQ-message database** for the operator's view of which messages failed where.

Templated from `quarkus-imperative-boilerplate` (with 11 poms — slightly more than the standard 9). Quarkus 3.20.2.2 per the version-matrix. Last commit 2025-10-10 (Claude config sweep only).

## How it fits

- **Consumes:** the DLQ subscriptions configured in its `application.properties` — one per fleet topic that has a DLQ configured.
- **Owns data store:** Postgres (DLQ message records + metadata).
- **Pairs with:** the GCP-side DLQ config + `quarkus-pubsub`'s in-code consumer pattern.

## Don't-do-here / gotchas

- **Adding a new DLQ subscription requires both GCP-side config + this service's `application.properties` update.** Otherwise the DLQ accumulates messages with no captor.
- **Database table growth** — DLQ messages accumulate forever unless there's a retention policy. Verify whether the schema has TTL handling.
- **Schema for the message payload** — likely stores the raw bytes + metadata + originating-topic-name. Be wary of growing this schema; messages can be large.
- **Quarkus 3.20.2.2** — older cohort per the version-matrix. Bump-eligible.
- **Closely related to the "Pub/Sub subscription audit" deferred meta-item** in PLAN.md — this service's presence in the fleet implies the audit gap (verifying every prod subscription has DLQ + max-attempts) has at least a partial answer.
