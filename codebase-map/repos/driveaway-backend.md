# driveaway-backend

## What it is
Spring Boot 3.2.12 / Java 21 multi-module service (package `cars.ship.driveaway`) for **driveaway logistics**: driver-facing load coordination, contact management, shipper-facing load views, and driver-document OCR. Keycloak-secured REST on `server.port: 8080` (`max-http-header-size: 32KB`). Uses `spring-commons` 3.29.0 for shared infra (`WebClientImpl`, `PubSubConsumer`, global exception handling). Google Cloud Vision drives OCR of driver-uploaded documents; Fingerprint Pro Server API (v7.0.0) is used for device/driver identification. Consumes CTMS posting/load-leg change events over Pub/Sub to keep a local `LoadInfo` projection. Since the last sync only minor DTO field additions (contact/attachment) and the Serena project file changed — no structural change.

## How it fits
- Consumes API of: `location-provider`, `media-proxy`, `notification-backend` (via `notification-client`), `posting-backend` (via posting-dtos), `metadata` — all through `spring-commons WebClientImpl`. **No explicit per-client connect/read timeouts** (fleet default; relies on `WebClientImpl` defaults). Also calls Google Cloud Vision (OCR) and Fingerprint Pro Server API.
- Publishes events to: Pub/Sub `notification` topic (`CONFIG_GCP_PUBSUB_TOPICS_NOTIFICATION`).
- Subscribes to: Pub/Sub `posting` subscription (`CONFIG_GCP_PUBSUB_SUBSCRIPTIONS_POSTING`) via `PostingPubSubSubscriber` (extends commons `PubSubConsumer`, `maxRetries` default 10); inbound posting/load-leg DTOs are converted by `LoadLegStatePubSubDtoEntityConverter` into local entities.
- Owns data store: PostgreSQL via Spring Data JPA + Flyway + Hibernate Envers; HikariCP `maximumPoolSize=10`. No persisted Vision/OCR cache observed.

## Key abstractions
- REST controllers (in `api-services/.../rest/`): `DriversLoadController` (driver load CRUD + status transitions, `API_DRIVEAWAY_LOADS_PATH`), `DriversContactController` and `ShipperLoadController` (both under `API_COMPANY_NAMESPACE_PATH`), `DecodingController` (`API_EXTERNALS_PATH`, OCR/decode), `PingController`, `AppController` (health), `RootController`.
- `PostingPubSubSubscriber` — `api-services/.../application/posting/impl/PostingPubSubSubscriber.java` — Pub/Sub consumer for CTMS posting events.
- `LoadLegStatePubSubDtoEntityConverter` — `api-services/.../converters/LoadLegStatePubSubDtoEntityConverter.java` — maps inbound posting/load-leg pub-sub DTOs to `LoadInfoDbEntity`.
- `OcrServiceImpl` — `infra/.../ocr/OcrServiceImpl.java` — Google Cloud Vision OCR of driver documents.
- Cron pollers (ShedLock-guarded): `NotificationCronPoller` and `LinkExpirationCronPoller` in `api-services/.../application/cron/poller/` — `@Scheduled` + `@SchedulerLock`.
- `db-entities` module — `DriveawayDriver`, `LoadInfoDbEntity`, `DriverActionDbEntity`, `Notification`.

## Don't-do-here / gotchas
- **ShedLock IS in place** (corrected — the previous shadow guessed it was missing): `NotificationCronPoller` and `LinkExpirationCronPoller` are `@SchedulerLock`-guarded, so multi-replica deploys won't double-fire. Add `@SchedulerLock` to any new `@Scheduled` method.
- **No REST-client timeouts** on outbound integrations (notification, posting, media-proxy, location-provider) — `WebClientImpl` defaults apply. Verify those defaults are bounded.
- **Cloud Vision OCR is a synchronous external call** — large/slow OCR blocks the request thread; drivers see latency. Consider async + callback.
- **Fingerprint Pro Server API in the identification path** — a third-party SaaS call; verify timeout and whether it fails open or blocks the driver.
- **HikariCP pool 10** — tight under concurrent driver + cron load; right-size after pool-wait metrics.
- **Pub/Sub subscription/topic names are env-driven** — verify env wiring before any topic rename in upstream posting-backend.
